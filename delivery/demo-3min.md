# AutoGrader 三分钟演示脚本

用途：赛事提交视频录屏。画面中的哈希索引实验报告与 rubric 是合成演示材料，不是真实学生作业；演示时保持这句说明可见。

| 时间 | 画面与操作 | 解说要点 |
| --- | --- | --- |
| 0:00–0:20 | 打开三案例页 `https://autograder-sotv.onrender.com/`，指向新案例 | 教师面对完整实验报告，要找值得核对的问题并保留最终给分权。系统提供可追溯的定性观察，而不是自动定分。 |
| 0:20–0:45 | 切到 `/realtime/`；选 TXT rubric 上传，展示 4 个条目、40 分和 SHA 预览 | 新 rubric 来自教师上传的原文；解析器只识别明确编号和分值，不补写标准。预览不消耗实时分析配额。 |
| 0:45–1:00 | 展示合成报告 TXT 与「开始分析」入口，随后回到三案例页 | 这份新报告与新 rubric 已在公网走完一次真实 L1→L4 全链，用时约 148 秒；视频不等待模型重新跑，也不把预置结果说成实时返回。 |
| 1:00–1:35 | 打开「哈希索引性能实验」教师视图；查看整篇优先观察的两条 | 第一条指出报告写 `2.16 / 0.03 = 7.2`，正确结果应为 `72`；第二条指出三组、单次、固定键实验不足以证明「任何规模和分布都恒定耗时」。Top N 是上限，不凑数。 |
| 1:35–2:05 | 点击两条的「查看原文」，再查看 R3 对应评价与折叠项 | 每条观察可跳回原文位置，强项与问题并列；有依据不等于解释自动正确，教师仍需判断。此例 L3 数值检查未形成机械结论，计算问题由 L4 定性评价发现，不能说成「L3 已验证」。 |
| 2:05–2:35 | 演示教师将一条观察标「准确」或修改文字，查看分数输入与完成校验 | AI 不预填分数；教师确认评价并输入自己的精确分数。演示性输入须口头说明是操作示例，不是实际教师评分。 |
| 2:35–2:50 | 点击生成评语草稿、导出教师工作表 | 评语草稿基于已确认内容；未完成教师给分时不形成总分。 |
| 2:50–3:00 | 回到首页，指向实时站与 GitHub 仓库链接 | 技术链：确定性原文索引 → rubric 条件下证据聚焦 → 按需验证 → 定性评价 → 教师复核。未做教师计时试验，不声称已证明节省多少时间。 |

录制前检查：先访问 Render 链接唤醒免费实例；确认首页有 3 个案例、新案例和两份原始 TXT 可打开；浏览器缩放设为 100%；关闭个人通知；不要在录屏中展示 API 密钥、job token 或真实学生材料。

若实时站冷启动或配额异常，直接从三案例页演示已生成的新案例；不要剪辑成「现场即时分析」的效果。
