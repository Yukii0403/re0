# AutoGrader · 教师协作式实验报告评阅

粤港澳大湾区 AI Coding 创新大赛参赛原型。AutoGrader 帮教师从计算机实验报告中找出值得核对的优点、问题和缺项，给出可回到原文的依据；**评价与精确分数由教师确认**。系统可据已确认内容生成整体评语草稿。

| 入口 | 用途 | 注意 |
| --- | --- | --- |
| [在线实时分析](https://autograder-sotv.onrender.com/realtime/) | 上传新报告，并选预置 rubric 或上传新的 TXT rubric；服务端调用模型 | 消耗共享配额，分析通常需数分钟；免费实例可能冷启动 |
| [三案例演示](https://autograder-sotv.onrender.com/) | 直接体验教师核对、原文跳转、给分与评语草稿 | **预生成产物**，打开案例不会重新分析 |

建议第一次体验先看三案例演示。它包含一份**合成**的哈希索引实验报告与新 rubric 的真实模型运行结果，以及 PDF、VerAs 文本案例。合成案例不是学生作业；预生成案例也不能冒充“现场实时分析”。

## 教师怎么用

1. 按 rubric 查看整篇优先观察与逐条评价。第一屏最多显示 3 条值得优先核对的观察，不为凑数填满；“缺项 / 论述不足”单列为待核查。
2. 通过“查看原文”核对依据。PDF 报告在新标签打开**原 PDF 的对应页**，缩放由浏览器 PDF 查看器控制；TXT 报告定位到原始文本。页码定位不等于逐字高亮或证明解释正确。
3. 教师确认、修改或否定评价，并自行输入各条精确分数。系统不替教师预填最终分数；未完成给分时不形成总分。
4. 根据教师已确认的内容生成整体评语草稿，并在浏览器本地导出教师工作表。

这套流程旨在减少教师查找依据的负担，**尚未通过教师计时实验验证节省了多少时间**；展示案例与自动化测试也不能证明开放性评价普遍准确，关键结论仍需教师核对。

## 实时分析支持范围

| 输入 | 当前支持 | 边界 |
| --- | --- | --- |
| 学生报告 | `.txt`、`.pdf`，默认上限 10 MB | 推荐先用 TXT；PDF 渲染更耗内存与时间，在免费实例上不保证每次成功 |
| 评分标准 | 预置 rubric，或新上传 UTF-8 `.txt`（上限 128 KB） | 新 rubric 须有明确编号及整数分值；上传前会显示识别结果供核对；**不支持任意 Word/PDF rubric 自动转换** |
| 教师复核 | 确认/修改评价、输入分数、生成评语草稿、下载工作表 | 当前没有教师账户、长期保存或多人协作功能 |

实时站与预置案例站共用 Render 免费实例，闲置后首次访问可能需等待冷启动。实时任务配额由服务端显示；它是**单实例的防滥用计数，不是可靠的费用上限**，实例重建后可能重置。模型费用上限应另在模型服务商处设置。不要为演示上传含个人信息、未获授权的真实学生报告：实时分析会把报告内容发给配置的模型服务商。

## 工作原理

```text
原始报告 + 教师 rubric
  → L1 确定性 Source Index（保留原文、顺序、位置与原件引用）
  → L2 rubric 条件下的证据聚焦（候选不是全文的替代品）
  → L3 按需进行计算、单位、图表规范或内部一致性核查
  → L4 带证据定位的定性评价
  → 教师复核与给分 → 整体评语草稿
```

L1 不由 LLM 重写原文；模型解释与机械验证结果作为派生信息保留。L3 是**按需**检查，不保证每条 rubric 都有机械结论。评价中的引用可以回到原件，但引用准确也不自动意味着推断正确。设计细节见 [L1](design/L1-document-index.md)、[L2](design/L2-evidence-focus.md)、[L3](design/L3-mechanical-verification.md)、[L4](design/L4-rubric-assessment.md)。

## 本地运行

需要 Node.js **22 或更高版本**。在仓库根目录执行：

```bash
npm install
npm start
```

打开 `http://localhost:8080/` 看预置案例，或 `http://localhost:8080/realtime/` 上传新材料。预置案例不需要模型密钥；**实时分析**须在服务端环境变量配置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`。不要把密钥写进仓库、网页或提交材料。可执行 `npm run selftest` 做本地自测。

部署到 Render 时选择 **Web Service / Docker**（不是 Static Site），配置上述三个环境变量；仓库提供 [Dockerfile](Dockerfile) 与 [render.yaml](render.yaml)。健康检查路径为 `/api/cases`。静态托管只能展示 `fixtures/web/` 内的预生成案例，不能上传新报告并运行模型。

## 仓库内容与复现边界

- `src/`：分析链、教师视图、服务端与自测脚本。
- `design/`：分层设计、数据契约与示例。
- `fixtures/web/`：已生成的三案例静态站；`fixtures/realtime/`：实时站前端。
- `delivery/`：演示脚本与提交辅助材料。

公开仓库不包含 API 密钥、用户上传件、原始评测数据集和部分原始报告。因此，**克隆仓库即可查看预置网页并运行自测，但不能仅凭仓库重跑所有历史实验或案例生成过程**。公开案例的来源在站点清单中标注。[VerAs 评估计划](design/evaluation-plan-veras.md)保留了早期自动给分研究设想和过程记录，**不是当前比赛版的功能或效果声明**。
