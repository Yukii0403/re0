# AutoGrader · L1 设计（极简版）

> 适用输入：**PDF 与 docx 的纯文本作业**。不做手写、不做扫描件。
> 实现：`src/l1.mjs` 单文件。测试：`src/_selftest.mjs`（合成夹具）、`src/_realtest.mjs`（真实文件）。

---

## 0. 一句话

**输入一份作业，输出两个文件：原文 `.txt`（逐字）+ 索引 `.index.json`（目录）。索引只负责指路，一个字都不改。**

---

## 1. 核心判断：L1 不调用任何模型

索引是给 LLM **消费**的，不是给 LLM **生成**的。PDF/docx 都有文本层，判断"哪行是图注、哪行是代码"纯靠规则就够。

规则生成 → 零幻觉 → 那些为了"不信任生成内容"才存在的机制（置信度、审阅队列、patch 回放、gold set、指标矩阵）**全部不需要**。

连带删掉的三件事：
- ❌ **不做公式转 LaTeX** —— 那正是"改变原文"
- ❌ **不做图注配对、图内数据抽取、语义摘要**
- ❌ **不做阅读顺序算法** —— 文本层给出的顺序就是顺序

需要看图 / 看公式时，索引给出**页码**，下游按需把整页渲染成图交给多模态模型。多模态能力保留为**按需消费**，不作为 L1 的固定成本。

---

## 2. 两条可机械校验的断言

**① 逐字不变**

```
entries.every(e => full.slice(e.start, e.end) === e.text)
```

**② 一行不丢**

```
块内行数合计 === 非空原文行数
```

第二条是补上的 —— 光靠第①条只能证明"没改字"，证明不了"没丢行"。两条都过，才算"不改变原文任何信息"。

**精确表述**（不过度承诺）：`.txt` 保留原文字符序列与顺序；**表格的行列结构、原图的像素内容不在文本层里，因此不在索引范围内**。图必须有图注才能进索引，无图注的图 L1 看不见 —— 这是"只做文本"的已知代价。

---

## 3. 三步流程

```
1. 抽取（原文，不改一字） → 2. 打标（纯规则） → 3. 出索引
```

### 步骤 1 · 抽取

| 输入 | 做法 |
|---|---|
| **PDF** | pdfjs 取文本层；同一 `y` 上聚成行；**同一 y 上水平间隙超过 1.8 倍字号就断开**（否则双栏的两栏文字会被拼成一行） |
| **docx** | 解压取 `word/document.xml`，**按 `w:body` 子节点顺序**遍历 `w:p` / `w:tbl` |

### 步骤 2 · 打标

**docx 有 XML 结构和真实字体名，判据可靠。PDF 没有** —— pdfjs 给的是内部字体 id（`g_d0_f1`），不是真实字体名。

| 类型 | docx 判据 | PDF 判据 |
|---|---|---|
| `header` / `footer` | 在页顶/页底 8% 内 + 文本（数字归一化后）跨页重复 | 同左 |
| `heading` | `w:pStyle` 命中 `Heading1-6`；或字号 ≥ 正文 ×1.10；或**编号 + 短 + 无句末标点** | 字号 ≥ 正文 ×1.10；或**编号 + 短 + 无句末标点** |
| `figure` | 含 `w:drawing` / `w:pict`；或文本以 `图 N` 开头 | 文本以 `图\s*N` 开头 |
| `table` | 含 `w:tbl`；或文本以 `表 N` 开头 | 文本以 `表\s*N` 开头 |
| `formula` | 含 `m:oMath`；或整行是 `(N)` | 字体名含 math；或整行是 `(N)`；或数学符号密度 ≥ 0.30 |
| `code` | 字体名命中等宽名单 | 语言关键字开头；或**相对左边距缩进 8~6×字号 且不含中日韩字符**；或延续上一行 |
| `paragraph` | 其余 | 其余 |

### 步骤 3 · 出索引 + 合并段落

块文本按行拼成 `full`，顺序查找偏移。然后把**同一段的视觉行合并成一个块**（行距 ≤ 同字体同缩进的最小行距 ×1.15，且左右边界一致）。

合并只改变索引粒度，`.txt` 字节完全不变 —— 因为 `full` 始终等于所有行以 `\n` 相连。

### 步骤 3b · 最小表格行列还原

把表格行还原成**可机械查询的对象**，让下游能用 `(列头, 行标签)` 唯一确定一个值，而不是靠子串猜。
**结构只写进索引，正文一个字符都不动。**

列边界的来源（**被真文件推翻两次后才定下来，见 §4 ⑤**）：

| 来源 | 列边界的判据 |
|---|---|
| **PDF** | ① **行间 x 对齐**：连续 ≥2 行在 ≥2 个相同 x 上都有单元格起点 → 这些是表的行；② **item 边界切格**：单元格 = 一串非空白 item，夹在中间的空白 item（内边距）算分隔。**不使用文本里的空格数，也不用宽空白的宽度** |
| **docx** | 制表符（`w:tc` 就是真单元格） |
| **手工/示例文本** | 2 个以上空格（回退判据；**PDF 行永不使用**：几何行一定带 `cell_breaks`，哪怕是空数组） |

判据全是机械的：连续且**真正相邻**的行单元、列数 ≥2 且一致 → 成表；首行不含数字 → 判为列头。
`truncated` 用来把「因为列数不同而被排除的那一行」指出来 —— **截断本身要可见，不静默丢行。**
**表头可能在表体之外**：真实文档里表头常居中/跨列，与表体的列位置不对齐，所以还会看「紧邻其前那一行」。

两个为下游准备的字段（见 §5）：

- **`key_query_safe`** = `header_detected && !truncated`。这是**允许用于键值查询**的机械条件：
  有列头才有列名可查；没截断才保证行是全的。为 false 时下游必须放弃键值查询，**不得降级成猜测**。
- **`cell_split_source`** = `pdf_geometry` / `docx_cell` / `text_wide_space` / `mixed`。
  这是列边界的**派生来源** —— 三种依据的确定性并不相同，标注出来，下游才能自己决定信不信。
  把"结构化"当成同一等级的确定事实，是这轮明确要避免的事。

## 4. 真正难的六件事（都是实测踩出来的）

### ① 代码块的缩进在文本层里根本没有空格字符

Chromium / Word 打出来的 PDF，缩进是靠**文字定位**实现的，文本层里没有前导空格。原始设计用"缩进 ≥2 空格"判代码，在真实文件上**只认出代码块的第一行**。

改用 **`x` 坐标相对正文左边距反推缩进**：实测正文 `x=45.0`，代码 `51.0 → 70.8 → 90.6`（每级约 19.8pt）。加上下界（≥8pt）和上界（≤6×字号，防止双栏的栏偏移被当成缩进）后，整个代码块一次认全。

### ② 正文字号不能用中位数

中位数会被**数量多但字数少**的行带偏：代码行、表格行、页眉页码全是小字号。一份 4 页报告用中位数算出正文 = 9pt（真实是 10.5pt），所有二级标题就都判不出来了。

改用**按字符数加权的众数** —— 正文占的字符数最多，稳。

### ③ 标题的字号比可能只有 1.14

实测 h2 = 12pt、正文 = 10.5pt，比值 **1.143**。原阈值 1.15 刚好把它挡在外面，17 个标题一个都认不出。

阈值降到 1.10，**并补一条不依赖字号的规则**：编号（`1`、`5.1`、`第1章`）+ 长度 ≤40 + 不以句末标点结尾 → 标题。编号比字号可靠得多。

### ④ 编号正则会误吃小数

`^[0-9]+(\.[0-9]+)*[\s、.．]` 会把表格里的 `0.861 9.8` 当成"0. 号标题"。收紧为**每段 1~2 位数字 + 后面必须跟分隔符而不是数字或小数点**：`0.861` 不再是标题，`1.1 研究背景` 仍然是。

### ⑤ 文本层里的空格数不可信 —— 表格列间距就是**一个**单空格

这是做表格适配器时踩的，也是本项目第三次遇到「子串/文本匹配在真实数据上失效」。

真实 PDF 里那张消融表在文本层长这样（`JSON.stringify` 后的原样）：

```
"配置 验证准确率 训练时长(min)"
"baseline 0.812 6.4"
"+ attention + 数据增强 0.861 9.8"
```

**单元格之间只有一个空格**。于是两件事同时不成立：
- 「2 个以上空格 = 列边界」这条规则在真文件上**认不出任何一张表**；
- 「按单空格切列」也不行 —— `+ attention + 数据增强` 本身含单空格，会被切成 6 列。

**几何才可信。** 同一个 `y` 上，item 之间的空白 item 宽度（相对字号）：

| 场景 | 空白 item 宽度 / 字号 |
|---|---|
| 表格列间隙（Chromium 打的 PDF） | **12.2 / 14.7 / 18.9 / 20.8 / 26.2 / 28.2** |
| 正文里因换行产生的空格 | **0.82** |

两者差了 15 倍以上，于是第二版取 **3 倍字号**作阈值：抽取时把「宽空白 item」的位置记成列边界区间。

顺带一个只有真文件才暴露的细节：pdfjs 为对齐空白产出的那个空格 item，`width` 会**跨越整个列间隙**（例如 `x=86.2 w=253.7`），导致下一个 item 的间距算出来是负数。所以判据用 **`width / font-size`**，不能用相邻 item 的 x 差。

### ⑤b 但「宽空白 = 列分隔」在真实 LaTeX PDF 上**方向是错的**（第二次推翻）

拿一份真实论文（CS3223 实验报告，LaTeX/acmart 排版）一测就露了：一张 5 列的表被切成 4 列，
**行标签和第一个数据值被并进了同一格** —— `"Run 1 0.25" | 9 | 11 | 0.31`。

量出来的原因很直接（同一行的空白 item）：

| 位置 | 空白 item 的 width/size |
|---|---|
| 行标签 → 第一个数据列（**真正的列分隔**） | **1.4** |
| 每个数据格**内部**（单元格内边距） | 9.8 / 12.1 / 12.1 |

也就是说：在这类 PDF 里，**宽空白是单元格内边距，不是列分隔**。按宽度阈值切，列就切在了错误的位置。
（`Run 1` 与 `0.25` 之间只有一个 1.4em 的空白，和正文词间空格同量级 —— 靠宽度永远分不开。）

**真正稳定的是结构本身：列位置跨行严格对齐。** 同一张表里 `0.25 / 0.21 / 0.18` 的起始 x 全是 **260.3**，
`9 / 5 / 4` 全是 **353.3**，`11 / 14 / 9` 全是 **449.3**，`0.31 / 0.25 / 0.21` 全是 **550.5**。
（行标签列是右对齐的，所以它的起点会变 —— 因此只要求"所有行都共有的位置"，不要求每列都参与。）

于是第三版判据（现在是定版）：

1. **行间 x 对齐**：连续 ≥2 行在 ≥2 个相同 x 上都有单元格起点 → 这些行构成一张表。
2. **item 边界切格**：单元格 = 一串非空白 item；夹在中间的空白 item（内边距）算分隔。
   item 边界比文本空格可靠：`Average Time (ms)` 是一个 item，`+ attention + 数据增强` 也是一个。
3. 对齐这道闸只写在**抽取阶段**：没有对齐的行（正文段落）根本不带 `cell_breaks`，
   于是永远切不出多格 —— 段落里恰好有个空格不会变成"两列"。

同一份样本上改完之后：那张表还原成 **5 列**，列头是跨列的
`Join Plan | Index-join | Merge-join | Hash-join | Nested-join`，行是 `Run 1 | 0.25 | 9 | 11 | 0.31` ✓。

**教训（第三条"子串/宽度类直觉在真数据上失效"）**：一个判据在一种 PDF 生成器上标定出来，
不代表它在别的生成器上成立。**宽度是排版副产物，位置对齐才是结构。**

### ⑥ 表格的列数必须一致，不一致就显式标截断

一个「表格区」要求列数相同。但真文档里常有缺格/合并单元格的行 —— 如果直接不认，那一行就**静默消失**了。
所以表上带 `truncated` + `truncated_at`：把被排除的那一行指出来，让下游看得见。**宁可不认，也不猜错；但丢了什么必须说。**

## 5. 输出

```
工作目录/
  实验二.pdf.txt              原文逐字（\n = 行/块边界，\t = 表格单元格边界）
  实验二.pdf.index.json       目录
```

**命名带上原始扩展名**：`report.pdf` → `report.pdf.txt`。若按"去掉扩展名"命名，同一目录下的
`report.pdf` 与 `report.docx` 会都写成 `report.txt` 而**互相覆盖**（这个 bug 是在真实测试的产物清单里发现的）。

索引条目：

```json
{ "id": "e0008", "type": "figure", "num": "3", "level": null,
  "page": 3, "lines": 1, "start": 132, "end": 149,
  "text": "图 3 不同学习率下的验证损失曲线" }
```

`level` 仅 `heading` 有值。`lines` 是该块占的原文行数。`page` 是 PDF 专有，docx 为 `null`。
`table_id` 指向同级的 `tables[]`（不属于任何表为 `null`）；`cell_breaks` 只在识别出列边界时才写。

表格结构（**索引独有，正文里没有**）：

```json
"t0001": {
  "id": "t0001", "caption_entry": "e0009", "entry_range": "e0010-e0013",
  "header_detected": true, "column_count": 3,
  "columns": [ {"text":"配置","start":162,"end":164}, … ],
  "rows": [
    { "label": "baseline",
      "cells": [ {"text":"baseline","start":183,"end":191},
                 {"text":"0.812","start":193,"end":198},
                 {"text":"6.4","start":200,"end":203} ] }, …
  ],
  "truncated": false, "truncated_at": null,
  "key_query_safe": true, "cell_split_source": "text_wide_space"
}
```

于是 `(列头="验证准确率", 行标签="+ attention")` → `"0.847"` 是**一次键值查询**，不是一次猜。
每个单元格同样满足全项目唯一的那条断言：`full.slice(start, end) === text`。

## 6. 明确不做

- ❌ 手写 / 扫描件
- ❌ 公式转 LaTeX、代码语言识别
- ❌ 裁图、抽图内数值、图注配对
- ❌ 语义摘要、`semantic_role` 标签
- ❌ 跨页表格合并、**合并单元格 / 跨行单元格的还原**
- ❌ 双栏 PDF 的阅读顺序（只给 `possible_two_column` 警告）
- ❌ 置信度、审阅队列、patch 回放
- ❌ 任何模型调用

**跨页表格不合并**：它本来就是两块文本，索引里就是两条 `table` 条目。下游想合自己去合。

**合并单元格还原不出**：它会让该行列数变少，于是表在那一行被截断（`truncated: true`）。
这是「宁可不认，也不猜错」的代价，已经显式标出来了。

**双栏那份是唯一没解决的**：顺序完全乱（`warnings` 里已标 `possible_two_column`）。但注意 —— **171 条依然全部是原文逐字子串，行覆盖 172/172**。也就是说双栏只影响"读起来顺不顺"，不影响"证据能不能回溯"。这是可以接受的降级。它的 `cell_breaks`（来自两栏栏间距的宽空白）**不可信** —— 已由 `possible_two_column` 警告覆盖，且没有因此误判出任何表。

回归测试 `src/_selftest.out.txt` **192 项全部 PASS**，覆盖：逐行判类、编号抓取、标题层级、页眉页脚识别、段落合并边界、自写 XML 保序与实体解码、docx 表格 `\t` 分隔、偏移对齐（重复行 / 缺失块 / 空块）、**表格行列还原的边界**（列数不一致 / 单行不成表 / 单空格不认 / 首行含数字 / docx 多行整表 / 几何优先 / 图注在下方），发布示例自洽（索引 + 5 份契约）。

## 8. 依赖与已知限制

**依赖只有两个**（纯 JS，无原生模块）：`pdfjs-dist`、`fflate`。

XML 解析**自己写**（约 90 行）：docx 的 XML 很规整，自写反而能原生保证"按文档顺序"——通用解析器会把同名兄弟节点合并成数组，顺序被静默打乱。顺带把 `fast-xml-parser@5`（6 个传递依赖）整个去掉了。

本机 npm 官方源不通，且沙箱拦截删除会导致 `npm install` 静默失败。可用的替代做法（已验证）：

```bash
curl -sL -o pdfjs.tgz https://registry.npmmirror.com/pdfjs-dist/-/pdfjs-dist-6.3.289.tgz
mkdir -p node_modules/pdfjs-dist && tar -xzf pdfjs.tgz -C node_modules/pdfjs-dist --strip-components=1
# fflate 同理
```

**已知限制**（都是"只做文本"的固有代价，不是 bug）：
1. **双栏 PDF 顺序不可信** —— 只给警告，不修。其 `cell_breaks` 也不可信
2. **扫描页无文本层** —— 该页标记 `no_text_layer`，无索引条目
3. **合并单元格 / 跨行单元格还原不出** —— 该行会让表在那一行截断（`truncated: true` + `truncated_at`），**不静默丢行**
4. **无图注的图看不见** —— 图注行是图在索引里的唯一代理
