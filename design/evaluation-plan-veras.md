# AutoGrader · 用 VerAs 评估 L1–L4 的评分准确性（计划）

> **VerAs = "Verify then Assess"（AIED 2024，Atil / Sheikhi Karizaki / Passonneau）** —— 它不是评估工具，
> 而是①一套**公开数据集**（有教师侧 gold）+ ②一套**评估协议与可比数字**。我们用它的数据当 gold、
> 用它的协议当标尺，把我们的 L2→L4 放进去量。
>
> 结论先说：**在这份数据上能严格评的是 L2/L3/L4；L1 在这份数据上评不了**（见 §1.2），
> L1 的位置用"保真不变量 + 文本损伤敏感性实验"补。

## 1. VerAs 给了我们什么

### 1.1 数据集（已核实：公开、无需登录）

DOI `10.26208/BWE2-BR31`（Penn State Data Commons，2022；3.6 MB zip + readme）

| 项 | 内容 |
|---|---|
| 规模 | **1078 份 Pendulum + 1005 份 Newton** 实验报告 |
| 文本形态 | **纯文本**（txt），只含**讨论 + 结论**两节；公式已转 LaTeX；blank-line 分段、每段一行 |
| 评分标准 | **docx**（各 2 个 part）：Pendulum **7 维**、Newton **8 维**；**每维 0–5 六点量表**（rubric 只定义 1–5 五级，**0 = 未涉及该维度**） |
| 两种评分策略 | ①5 级量表（Pendulum 的 R1/R2/R3/R4/R7）②**按条项计分**（R5/R6：5 条各 1 分，Σ=5） |
| 标签 | `PendulumLab.csv` / `NewtonLab.csv`：`Dimension 1..7/8`、`source`、`status`、`TA`、`Reported Score`/`Max Score`、**`RescaledTA`**、**`RescaledRater`** |
| 人工上限 | 论文报告：评分者间 Pearson **0.72**（Pendulum）/ **0.69**（Newton） |

### ★★ 实测纠正了计划里的两条假设（2026-09-24，已核实到数据）

1. **release 里没有 `GT` 行。** readme 说 `source` 可能是评分者 id 或 `GT`，但实际文件里 `source ∈ {AW, VN, GD, CZ, AB}`。
   真相是：**`source=GD` 的行就是 gold**（`status=common` 多为多评分者多数，`discussion` 为研究者共识）；
   Pendulum 共 **105 行**是 GD（93 common + 12 discussion），其余 973 行是**单评分者**标签。
   → 评估主集用这 105 份 GD 行；单评分者行可作扩展（噪声更大）。
2. **人类一致性上限算不出来。** 每份报告**只有一行**（1078 唯一 id = 1078 行），没有逐评分者分开的行 →
   无法自算 rater-vs-GT 的 Spearman/MSE。**只能引用论文的 Pearson 0.72 / 0.69 作为人类上限。**
3. 顺带核实：`RescaledRater = Σ各维 / 满分`（成立，误差 < 0.02）→ 我们的总分可直接对齐它的口径；
   `RescaledTA = Reported Score / Max Score` → **TA 对比**可以直接做。
4. **L1 在这份数据上确实评不了**（txt 是作者抽好的）—— 但**rubric 是 docx，由我们自己的 L1 解析**，
   所以 L1 并非完全缺席；它的位置仍由保真不变量 + 文本损伤实验来保证。

**关键含义**：① 我们有 gold（`source=GT` 的行）；② 可以顺手算出比论文更细的**人类上限**（同报告多个评分者行 vs GT）；③ `RescaledTA` 让我们能回答一个很有说服力的问题：**我们 vs TA vs 共识评分者谁更接近共识**；④ rubric 文本随数据一起给 → 我们的 `strategy_source_ref` 有真实出处可指。

### 1.2 ★ 这份数据评不了 L1（必须说清楚）

数据集的 txt 是**数据集作者已经从 Word 里抽好的**。也就是说 **L1（解析）在这条链路上被绕过了**：
拿它做 L1 的准确率评估，量的是别人的解析器。

所以本计划里 L1 的位置是：
- **保真不变量**（已经实现且有回归）：逐字子串 + 行覆盖 + 表格每格 `slice(start,end) === text`；
- **P2 的文本损伤敏感性实验**：对我们自己的 PDF 夹具，把 L1 输出人为损伤（删一段 / 合并行 / 错列边界）→
  量**分数变化**，回答"L1 失真的代价有多大"。

若以后拿到原始 docx/pdf，再把"同一份报告的 L1 输出 vs 数据集 txt"直接对比，那才是 L1 的评分级评估。

### 1.3 VerAs 的评估协议（我们直接沿用，好让数字可比）

| 层 | 指标 |
|---|---|
| **总分** | MSE、**Krippendorff α_interval**、**Weighted Accuracy**（距离加权，论文公式 5） |
| **维度级** | 各报告各维度求平均的 **Spearman**、平均 α_interval |
| **verifier** | 二分类（该维度是否 >0）的 **Accuracy / micro-P / R / F1** + **多数类基线** |

论文参照数字（Pendulum / Newton，我们的对标线）：

```text
总分：  MSE 19.11   α_interval 0.77   weighted acc 0.91        （VerAs 最佳；基线 MSE 24.3–27.5）
维度：  Spearman 0.52 / 0.60，α_interval 0.46 / 0.54
verifier：Pendulum Acc 0.92 F1 0.91（多数类 0.92）；Newton Acc 0.81 F1 0.80（多数类 0.81）
        ★ 最难的 D6：Acc 0.61 / Rec 0.13 / F1 0.23（比多数类还差）
人类上限：评分者间 Pearson 0.72 / 0.69
```

## 2. 对应关系：VerAs 的模块 ↔ 我们的 L1–L4

| VerAs | 我们 | 说明 |
|---|---|---|
| （无） | **L1 解析** | 本数据上被绕过；用保真不变量 + P2 敏感性实验补 |
| **verifier**（该维度是否有相关内容 / 选 top-k 句） | **L2 Evidence Focus** | 同一个问题：**"这一维的内容在不在、在哪"**。L2 的 facet 覆盖率、`no_candidate`、引用绑定可直接算 verifier 的三项指标 |
| （无） | **L3 机械验证** | 我们的增量：VerAs 没有"对数字做机械核对"这一层。要专门量它对分数的贡献 |
| **grader**（在相关句 + 维度上给 0–5） | **L4 Assessment** | 形态对应：**每维一个可与 0–5 对齐的结论**。★ v0.3 起我们不产生分数 —— levels 维度给**候选档位**（L1–L5 + 超范围的 `outside_defined_levels`），评测侧再用**保守映射**折算成分数（见 §2.1） |
| 直接预测总分的基线 R2BERT | —— | 我们不做总分回归：总分由程序按叶子求和（这一点本身就是可对比的差异） |

**Rubric / profile 的落法**：每份 VerAs rubric 的**每个维度 = 一个 rubric 条目**（7/8 个**平级**叶子，
没有父项）；`levels` 维度（R1–R4/R7）取数据集 rubric 里**逐字切出来**的 5 列等级描述，`level_id = L1..L5`，
`strategy_source_ref` 指向 rubric 原文那一段；`points` 维度（R5/R6）取五条各 1 分的条项。
→ 顺带验证一件已修的事：**顶层直接挂叶子的 rubric，总分只能按叶子求和**（按 section 反推会漏，上一轮踩过）。

### 2.1 ★★ v0.3 的保守映射（`src/veras-map.mjs`，唯一口径）

v0.3 起 L4 **不产生分数**，但 gold 是 0–5。评测必须把"定性结论"折算成能与 gold 对齐的分值，
而**折算口径只能有一份**（三份脚本各写一套 = 本项目已踩过的坑）。规则：

| L4 结论 | 映射 | 说明 |
|---|---|---|
| `level_status=candidate`（1 档） | 该档分数 | 直接对应 |
| `level_status=candidate`（2 档，边界不清） | **取低界** | 保守：不取中点（中点等于替模型猜一个更细的档） |
| `level_status=outside_defined_levels` | **0** | ★ 对应 gold 的「未涉及该维度」。**这不是自造档位**（我们不产生档位），而是对齐 gold 的既有语义；它让"0 分"第一次可被机械表达 |
| `level_status=insufficient_evidence` / `not_applicable` | **null（弃权）** | 单列计数，**不参与任何分母**（弃权 ≠ 错，也 ≠ 0） |
| `judgment=satisfied`（points/binary） | max | — |
| `judgment=not_satisfied` | min | — |
| `judgment=partially_satisfied` | **null（弃权）** | ★ 我的判断：v0.3 的判断不含"做到几成"的定量信息，硬折算就是在替模型做**分数校准**（正是论证过不该追、且实测做不稳的事）。宁可弃权 |

- **只要有一个维度弃权 → 不给总分**（绝不用 0 补齐一个看起来完整的总分）；维度级指标仍按维度对计算。
- ★★ **`_mkveras.mjs` 已删掉自造的 `L0`**（回原始 rubric 核对：每维只有 5 列等级描述，**没有 0 的定义**）。
  我们此前合成的「未涉及该维度」是无出处的发明（污染 5 个 levels 维度、并逼模型在 1–5 里硬选 → R1 无分辨力）。
  0 的语义现在由 `outside_defined_levels` 承载 —— 这与它"通读可靠完整原文仍无相关内容"的定义严丝合缝。
- 副作用（预期内）：rubric 字节变了 → 之前跑过的产物绑的是旧 rubric → **全部失效**。
  `_evalveras --skip-done` 现在会**逐份核对产物里的 rubric sha**，不一致就重跑（旧版只看文件存在，会拿失效产物算指标）。

## 3. 要量的东西（比论文多三项，都是我们的差异化）

1. **弃权（abstention）**：`judgment = insufficient_evidence` / `not_applicable` 的比例，以及
   **非弃权部分的准确率**。报告要写成"覆盖率 × 准确率"，不能把弃权算成错、也不能悄悄丢掉。
2. **审查成本**：`review.required` 的比例，以及**自动放行部分的错误率** —— 这是"教师协作式"的核心卖点：
   在同等准确率下，我们让教师只看 X% 的条目。
3. **L3 的贡献与 fail 的有效性**：预测中隐藏 L3 结论做 A/B；再看 `fail` 与"GT 被扣分"的对齐度
   （precision / recall），回答"机械反证抓的是不是真的评分点"。
4. **误差归因（层次分解）**：把每个维度的误差归到
   ①L2 没找到内容 → ②找到了但引用绑不回（`dropped_*`）→ ③量纲/表格查不了（L3 unverified）→
   ④依据齐了但分数偏（L4 偏差）。**这一条就是"L1 到 L4 的评分准确性"里"哪一层的问题"**。
5. **稳定性**：同一批跑 2 次（温度 0），看分数变化幅度；以及**成本**（调用数、token、墙钟时间）。
6. ★★ **0 分覆盖（v0.3 新增，直指老病）**：gold=0 的维度，我们有没有把它认出来 ——
   - levels 维度：`outside_defined_levels`（映射为 0）；
   - points 维度：`not_satisfied`（映射为 min=0）。
   ★ 实测发现的口径缺口：`_evalveras` 现在的 `0命中` 只统计 levels 维度的 `outside`，
   points 维度的 `not_satisfied→0` **没被计入** → 会低估。统计时要**合并两类**（`map_kinds[i]==='outside'` 或 `pred[i]===0` 且 gold=0）。
   这条指标直接对应 VerAs 诊断里「0 分漏判 6/6」那个单一最集中偏差来源。

## 3.5 ★★ 验证协议（2026-09-24 定，holdout 运行必须遵守）

### ① gold 与产物隔离

```text
--run    只跑样本、锁定预测：进程内**只取样本 id**（连 gold 分数都不读进来）→ 落盘 predictions.<lab>.json
--score  另起一次进程，才读 gold → 出指标
```

- 旧版在**运行前**就读入并打印 gold，且与开发集共用目录 → 跑的人看得到答案，且产物可能互相顶替。
- 现在「预测锁定后才揭晓 gold」是**结构保证**（不靠自觉）：`--run` 的预测文件里没有任何 gold 字段；
  指标只能由 `--score` 新起进程算。
- **holdout 必须用独立名单 + 独立输出目录**（例：`--ids-from fixtures/veras/holdout/holdout.pendulum.json --out fixtures/veras/out-holdout`）。

### ② 失败即停，禁止读旧产物

- 旧版两个洞：**L3 失败仍跑 L4**；**L4 失败后仍读同名既有 `assessment.json`** 参与映射。
- 现在：任一层 `exit≠0` → 立刻停该样本，记 `failed:<层>`，**不读任何已有产物**；
  并且每层产物都要过「**本次生成**」校验（mtime 必须晚于本次样本开始时间），否则同样记 failed。
- 失败样本**一律不做预测**，在 `--score` 里单列，**不进任何指标**。
- `--skip-done`（仅核 rubric sha）**不足以**用于正式运行 —— 它无法区分"这份是新跑的"和"这份是上次留下的"。

### ③ 锁定口径，一次跑完

- `--run` **不支持续跑/跳过**（那会引入"哪几份是新跑的"这种不可比状态）。
- 正式运行前先用**开发样本**做**入口冒烟测试**（`fixtures/veras/smoke.ids.json`），
  把**代码 / 模型 / 提示词 / 映射 / 指标**全部固定下来；此后到 holdout 出数之前不再改。
- 正式运行用 `--strict`：有失败样本时返回非 0（让人必须看见）。

### ④ 报告必须包含（按**评分者组别**分开呈现）

| 量 | 说明 |
|---|---|
| **成功率** | 成功份数 / 总份数；失败按层归类 |
| **弃权率** | 样本级（总分不可给）+ **逐维**（哪一维最容易弃权） |
| **各档分布** | 每维 `assessed / outside / abstain` 三态计数 |
| **0 分覆盖** | 宽口径：映射为 0 的维度 ∩ gold=0 |
| **证据可回溯率** | findings 里"有原文定位或 L3 挂钩"的比例 |
| **送审率** | 条目级 `review.required` 比例（教师成本） |
| **成本** | 调用数 / prompt / completion / 墙钟 / 单份均值 |

### ⑤ ★★ 口径声明（必须随报告一起出现）

**分数映射指标（MSE / 偏置 / ρ / MAE）只是次要代理指标。**
gold 低分**并不能**证明系统指出的具体问题是对的，反之亦然 ——
真正要主张的是两条：**「该发现的问题发现了吗」**（0 分覆盖、concern 与 gold 低分的方向一致性）
与 **「指出的问题可不可核对」**（证据可回溯率）。分数指标只作参照。

**流程**：冒烟（dev）→ 固定口径 → `--run` 一次跑完 holdout → `--score --strict` 出报告。

#### 4.1 ★ 实测成本（单份报告，Pendulum 7 维，真实模型）

| 层 | 调用数 | prompt tokens | completion tokens | 墙钟 |
|---|---|---|---|---|
| L2（1 plan + 逐 facet 定位） | **20** | 175.4k | 7.2k | 34 s |
| L3（机械验证） | **1** | 13.3k | 2.2k | 12 s |
| L4（每维一次 + 重试） | **16** | 83.3k | 24.8k | 105 s |
| **合计** | **37** | **272k** | **34k** | **≈2.5 min** |

**两个成本杠杆（都在模型侧，不在我们侧）**：
1. **L2 的 facet 数是主要成本**：模型自己拆出 **20 个检索面 / 7 维**（≈2.9 面/维）→ 每份 20 次调用。
   想压成本就是压面数（facet 定义得更窄更少），但会牺牲检索覆盖 —— 这是要调的旋钮。
2. ~~**L4 的 `rationale ≤ 300` 硬闸会让调用数翻倍**~~ → **已改为软上限（2026-09-24）**：
   超过 300 字**不拒收、不改写**，只记 `over_limit` + 强制送审（`rationale_over_limit`）；
   仅保留 2000 字的工程上限防爆量。20 份那一轮开始按新口径计成本。

**外推**（按上面实测，顺序执行；并发 n 路则墙钟除以 n）：

| 样本量 | 调用数 | prompt tokens | 墙钟（顺序） |
|---|---|---|---|
| 1 份（已跑） | 37 | 272k | 2.5 min |
| 20 份 | ~740 | ~5.4M | ~50 min |
| 105 份（Pendulum 全部 GD gold 行） | ~3.9k | ~29M | ~4.4 h |

> 成本换算：`prompt_tokens × 单价_in + completion_tokens × 单价_out`（按你账号里 `deepseek-flash` 的单价乘）。

### P2 · 归因与消融（加分项，能做多少做多少）

| 消融 | 回答什么 |
|---|---|
| L4 输入**隐藏 L3 结论** | L3 对分数的实际贡献 |
| L4 输入**不给 L2 证据**（只给原文 + 维度） | L2 的价值（对应 VerAs 的 `W/o Verifier` 消融） |
| **L1 文本损伤**（删段/并行/错列） | L1 失真的代价（回答"L1 的评分准确性"） |
| 同批跑 2 次 | 稳定性 |

### 明确不做

- 不训练/不部署 VerAs 模型本体（论文未公开代码；我们也不是要复现它）；
- 不做中学短文那份数据（二值、无 grader，对我们的四层链路没有信息量）；
- 不做全量 2083 份（调用量与时间不允许，抽样分层已足够支撑"分布上是否成立"的结论）；
- 不把总分做成回归目标（总分仍由程序按叶子求和）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 20 份 × 15 维的样本量对各维度很薄（Spearman 置信区间宽） | 报告一律带 bootstrap 区间（与论文一致）；先做全维合并的汇总指标，再逐维看 |
| 报告只有讨论+结论，某些维度天然"材料不足" | 正好是 `insufficient_evidence` 的用武之地：**弃权 ≠ 错**，报告里分开计 |
| gold 本身有噪声（0.72/0.69 的上限） | 所有结论都以"是否达到人类上限"为标尺，不追求 1.0 |
| 300+ 次调用耗时长 | 后台跑 + 可选并发（3–5 份并行）；先跑 P0 的 20 份 |
| 维度文本是英文 LaTeX，我们的 rubric 适配层只做过中文/英文简单结构 | 先用手工校对的 canonical rubric（7/8 条），不依赖自动适配 |

## 6. 需要 Yukii 定的四件事

1. **P0 抽样规模**：我建议 Pendulum **20 份**（分层），够跑通全套指标；要不要加到 30–40？
2. **要不要顺手比 TA**（`RescaledTA`）：我建议要 —— "我们比 TA 更接近共识评分"比"我们接近评分者"更有说服力。
3. **抽样样本是否入仓**（20 份 txt 很小，约几十 KB；全量留在本地 + manifest 校验和）？
4. **P2 做到哪一档**：我建议至少做"隐藏 L3 结论"这一项（它是我们相对 VerAs 唯一的机制增量，不量就等于没证明）。
